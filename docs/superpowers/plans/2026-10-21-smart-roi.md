# Smart ROI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new ROI kind, `smart`, that finds an irregular hot sample's outline inside a user-drawn search area every frame, tracks it as it changes, and reports the sample, pixel-offset rings and dimensions in the live view, the TC-POWER live feed, playback and exports.

**Architecture:** One pure, deterministic detector/tracker (`analysis/smart_roi.py`) is the single source of truth. Live: an acquisition-frame listener runs a tracker per live smart ROI; results go to the TC-POWER feed and, as RLE-encoded label crops, into each WebSocket frame for the browser to draw. Recorded runs: a full-rate background job runs the same tracker over the stored frames and saves per-frame results; playback and exports read those, so they agree frame for frame. The browser never detects; it draws what the operator sends.

**Tech Stack:** Python 3.12 / FastAPI / numpy / **scipy (new dependency)** / zarr; React + TypeScript (node --test, tsc).

**Spec:** `docs/superpowers/specs/2026-10-21-smart-roi-design.md` (read it; this plan argues from it).

**One deliberate refinement of spec §7a:** stored per-frame results come from a full-rate job over the *recorded* frames (run at finalize, and on demand for ROIs added later), not from the live tracker during recording. This keeps the camera thread free of storage work and gives one code path for new and old runs; playback and export still agree frame for frame. The live view may differ from the stored track only in the first frames of a recording (the live tracker may already be locked from pre-run frames).

## Global Constraints

- Pixels only in v1; store a `units: "px"` field on dimensions and ring offsets (spec §6 units hook). No mm, no scale UI.
- Default rings `(5, 10, 25)` px, measured as bands 0–5, 5–10, 10–25 (spec §2, §7a).
- Relative rule default; edge at `cold + s·(hot − cold)` with `hot` = p99, `cold` = p20 of the search area, `s` = sensitivity default `0.5`, range `0.3–0.7` (spec §4; mockup values).
- States exactly `"searching" | "locked" | "holding"`; feed validity: locked → valid, holding → **valid with `state:"holding"`** until `HOLD_S = 1.0` s elapses, then searching → `valid:false` (spec §7b).
- `% change` baseline = first lock in the run; never reset (spec §7a).
- After falling back to searching, search area = last grown area ∩ (user outline dilated by `SEARCH_MARGIN_PX = 15`) (spec §7a).
- Over-range pixels excluded from edge estimation; an ROI region containing over-range pixels reports invalid as today (spec §4).
- Smart ROI may not be an armed-recording trigger ROI (spec §7a).
- Add scipy with `cd backend && uv add scipy && uv sync --extra dev --inexact` — **never** bare `uv sync` (strips PySpin).
- Every task: red-green TDD; strict mypy + ruff + pytest (backend), `node --experimental-strip-types --test 'src/**/*.test.ts'` + `npx tsc --noEmit` (frontend); colours via CSS tokens only (theme test).
- Bump `backend/flir_research_interface/__init__.py`, `backend/pyproject.toml`, and the `flir-research-interface` entry in `backend/uv.lock` (match by name) once per shipped task group. **Never restart the lab operator without Matt's go-ahead.**

## Review Focus

1. **Sample never stands out (cold run, RF off):** stays `searching`, feed `valid:false`, no numbers, no exceptions — test in Task 2.
2. **A hot electrode or second hot part inside the search area:** must keep the component overlapping the previous outline, not jump to the larger/hotter one — test in Task 2.
3. **Search outline drawn partly off-frame or degenerate (2 points, zero area):** parse rejects (<3 points) or clips; never crashes the feed for other ROIs — tests in Tasks 1 and 4.
4. **Saturated/over-range core (sample hotter than camera range):** edge still found from non-saturated pixels; sample stats invalid (over_range) like other ROIs — test in Task 2.
5. **Run where frame ids wrap/reset (A70 16-bit ids, reconnects mid-run):** job maps results by frame **index**, never by frame id comparison — test in Task 5.

### Task 2: Detector and tracker (pure)

**Files:**
- Modify: `backend/flir_research_interface/analysis/smart_roi.py`; `backend/pyproject.toml` + `backend/uv.lock` (add scipy, see Global Constraints)
- Test: `backend/tests/test_smart_roi.py`; fixture `backend/tests/fixtures/smart_roi_20261020.npz` (captured, see Step 1)

**Interfaces:**
- Consumes: `SmartRoiSpec` (Task 1).
- Produces:
  - `@dataclass class SmartResult: state: Literal["searching","locked","holding"]; valid: bool; bbox: tuple[int,int,int,int] | None  # x0,y0,x1,y1 half-open; labels: np.ndarray | None  # uint8 crop of bbox: 0 none, 1 sample, 2..k = ring i-1; sample: dict[str, float | None]  # mean_c,max_c,min_c; rings: list[dict[str, Any]]  # {"inner_px","outer_px","mean_c","max_c","min_c"}; dims: dict[str, Any] | None  # area_px,length_px,width_px,perimeter_px,centroid_x,centroid_y,sharpness_c_per_px,area_change_pct,length_change_pct,width_change_pct,units:"px"; edge_level_c: float | None; over_range: bool`
  - `class SmartTracker: def __init__(self, spec: SmartRoiSpec, width: int, height: int) -> None; def update(self, celsius: np.ndarray, t_s: float, over: np.ndarray | None = None) -> SmartResult; def reset(self) -> None`
  - Constants `HOLD_S = 1.0`, `SEARCH_MARGIN_PX = 15`, `MIN_CONTRAST_C = 2.0`, `MIN_AREA_PX = 20`.
- Algorithm (decided here; tests pin it): edge level per Global Constraints (fixed rule: `fixed_c`); candidate = pixels ≥ level inside the current search mask, over-range excluded; `scipy.ndimage.label`; choose the component with the **largest overlap with the previous outline** (largest area on first lock); `binary_fill_holes`. Reject (→ hold) if contrast `< MIN_CONTRAST_C`, area `< MIN_AREA_PX`, component touches the search-mask border, or area changes `> 35 %` vs previous lock in one frame. Hold up to `HOLD_S`, then searching. Search mask after a lock = previous outline dilated by `max(rings_px) + SEARCH_MARGIN_PX`, intersected with the user outline dilated by `SEARCH_MARGIN_PX`; before first lock = user outline. Rings from `distance_transform_edt(~sample)`. Length/width = extent of the sample's pixel coordinates projected on its principal axes (eigenvectors of the coordinate covariance), max − min + 1. Perimeter = count of sample pixels with a 4-neighbour outside. Sharpness = mean |∇T| (np.gradient) on perimeter pixels. Ring stats use `ring_emissivity` via the existing `roi_field`/`_optical` path when set.
